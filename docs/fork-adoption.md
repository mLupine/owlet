## Client choice

PyPI's latest advertised release was independently checked as `pyowletapi==2025.4.10`. Its installed `api.py` and `sock.py` were inspected alongside the original 2025.4.1 and both bundled forks. The external latest still directly coerces fields, can abort normalization on malformed fields, strictly formats aggregate timestamps and has no shared asyncio auth lock. It does not expose the per-property normalization ownership/failure isolation needed here. Vendoring the adapted idomp/Lucas client keeps protocol changes inspectable and testable, and avoids depending on a separate wheel maintainer for fixes. It transfers maintenance responsibility to this repository; MIT notices are included.

We retain original BASE_STATION_ON_CMD payloads, restrict writes to that command plus APP_ACTIVE, expose pending/confirmed/unconfirmed command state, verify matching subsequent cloud readback, and sanitize failures. Acceptance is distinct from confirmation; a 30-second confirmation timeout warns without failing the accepted service request. Token invalidation/retry compares the request's rejected token under the shared refresh lock, preventing late 401s from discarding another sock's refreshed token. Credential changes invoke immediate persistence callbacks and finally snapshots even when discovery/polling/optional identity operations fail.

## Remaining evidence boundaries

No cloud login, device actuation, phone delivery, vendor code semantics or browser dashboard rendering was verified. A loopback HTTP server proves the actual HA/client path for both region selections, not public backend acceptance. Recorder tests preserve real synthetic DB rows and metadata IDs; they are not a backup/restore test of a customer's production database. Duplicate serials returned by separate regional accounts still represent one existing serial-based HA identity; distinct physical devices sharing a serial cannot be independently represented without a separately designed migration.

## Cross-family behavior corrections

[Cross-family review decisions](cross-family-review-decisions.md) records every accepted or rejected finding from the Claude review and coder re-review. Freshness defaults off for every entry without an explicit option. Enabled freshness preserves independent property timestamps and limits cached idle suppression by source-health evidence. Options saves reject thresholds no longer than the polling interval; persisted combinations remain unchanged and are diagnosed.

Dutch `nl.json` and `icons.json` use the exact archived Lucas head `3314a7f9e08754b9e39d57cd8334b7db373ec1b9`, introduced in commit `a0d9cc57f26d56ca740ffff59ec3982215ac9df5` and inherited by idomp. Names and available state labels were retained. Missing current keys were translated, obsolete placeholder-bearing descriptions were removed, and freshness options/errors were reconciled. `icons.json` is byte-identical to that source. The current HA 2026.10.2 baseline loads this metadata through its icon helper.
